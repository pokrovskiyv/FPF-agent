# Part E – The FPF Constitution and Authoring Guides

- [E.1 - Vision & Mission: “Operating System for Thought” (E.1)](01-e1-e1-vision-mission-operating-system-for-thought.md) — Explains why fragmented tools and drifting vocabularies break ideas in transit, and what a universal thinking scaffold should do instead.
- [E.2 - The Eleven Pillars (E.2)](02-e2-e2-the-eleven-pillars.md) — Lists the eleven non-negotiable commitments every part of the framework must honour to stay coherent and evolvable.
- [E.2.DA - FPF Pillar-Adequacy Evaluation CharacteristicSpace (E.2.DA)](03-e2da-e2da-fpf-pillar-adequacy-evaluation-characteristicspace.md) — Provides a structured checklist for judging whether a whole framework edition adequately fulfils all eleven foundational commitments.
- [E.3 - Principle Taxonomy & Precedence Model (E.3)](04-e3-e3-principle-taxonomy-precedence-model.md) — Defines how principles are categorised and which category wins when two principles pull in opposite directions.
- [E.4 - FPF Ecosystem Family Architecture (E.4)](05-e4-e4-fpf-ecosystem-family-architecture.md) — Maps what belongs to the core framework versus domain extensions, publication carriers, and access services so authors can place new work correctly.
- [E.4.FPF - First Principles Framework Form and Publication-or-Access Carrier Assembly (E.4.FPF)](06-e4fpf-e4fpf-first-principles-framework-form-and-publication-or-acc.md) — Explains how to treat the framework itself as one versioned edition rather than a pile of files or patterns.
- [E.4.PFAD - Principle-Framework Architecture Decision (E.4.PFAD)](07-e4pfad-e4pfad-principle-framework-architecture-decision.md) — Provides a decision template for choosing a framework's purpose, pattern set, dependencies, and publication form before building it.
- [E.4.DPF - Domain Principle Framework Authoring and Publication-or-Access Carrier Assembly (E.4.DPF)](08-e4dpf-e4dpf-domain-principle-framework-authoring-and-publication-o.md) — Guides a team through creating a domain-specific or local practice framework grounded in the core, from source material to publication carrier.
- [E.4.DPF.DA - Domain Principle Framework Package-Adequacy Evaluation CharacteristicSpace (E.4.DPF)](09-e4dpf-e4dpfda-domain-principle-framework-package-adequacy-evaluati.md) — Evaluates whether a domain or local framework package is good enough for its declared audience and use, not just internally consistent.
- [E.4.PFR - Pattern-Framework Relation and Edition Discipline (E.4.PFR)](10-e4pfr-e4pfr-pattern-framework-relation-and-edition-discipline.md) — Defines the different kinds of relations between patterns and frameworks so dependency, specialisation, and publication are not confused.
- [E.5 - Four Guard‑Rails of FPF (E.5)](11-e5-e5-four-guardrails-of-fpf.md) — Names four structural protections that prevent tool jargon, notation lock-in, circular dependencies, and disciplinary bias from eroding the core.
- [E.5.1 - DevOps Lexical Firewall (E.5.1)](12-e51-e51-devops-lexical-firewall.md) — Bans technology-specific terms from normative content so the framework does not age with the tools it mentions.
- [E.5.2 - Notational Independence (E.5.2)](13-e52-e52-notational-independence.md) — Requires concepts to be defined in plain language first so meaning does not depend on any particular diagram style or syntax.
- [E.5.3 - Unidirectional Dependency (E.5.3)](14-e53-e53-unidirectional-dependency.md) — Enforces one-way imports so volatile layers like tutorials can never pull the stable core into rapid revision cycles.
- [E.5.4 - Cross‑Disciplinary Bias Audit (E.5.4)](15-e54-e54-crossdisciplinary-bias-audit.md) — Provides five bias lenses to check whether "universal" rules secretly favour one field's metaphors over others.
- [E.6 - Didactic Architecture of the Specification (E.6)](16-e6-e6-didactic-architecture-of-the-specification.md) — Explains how the specification is ordered to ease readers from concrete intuition toward formal depth without burying entry points.
- [E.7 - Archetypal Grounding Principle (E.7)](17-e7-e7-archetypal-grounding-principle.md) — Requires every abstract rule to be illustrated with two canonical real-world examples so universality is demonstrated, not merely claimed.
- [E.8 - FPF Authoring Conventions & Style Guide (E.8)](18-e8-e8-fpf-authoring-conventions-style-guide.md) — Sets the required shape, voice, and section order for every pattern so practitioners can recognise when and how to use it without reverse-engineering the text.
- [E.8.ECSPF - Evaluation CharacteristicSpace FPF Pattern Publication Form (E.8.ECSPF)](19-e8ecspf-e8ecspf-evaluation-characteristicspace-fpf-pattern-publicati.md) — Governs how to publish a reusable evaluation rubric as a proper pattern so the coordinate table stays practitioner-readable and bounded.
- [E.9 - Design‑Rationale Record (DRR) Method (E.9)](20-e9-e9-designrationale-record-drr-method.md) — Provides a minimal record format for capturing why a content decision was made and what alternatives were rejected, so future maintainers can replay intent.
- [E.9.DA - DRR Decision-Adequacy Evaluation CharacteristicSpace (E.9.DA)](21-e9da-e9da-drr-decision-adequacy-evaluation-characteristicspace.md) — Checks whether an existing decision record is actually strong enough to drive the next drafting step, not just formally complete.
- [E.10 - Unified Lexical Rules for FPF (E.10)](22-e10-e10-unified-lexical-rules-for-fpf.md) — Gives a single entry scan for detecting when a word in conformant text is hiding which kind of thing it names or which relation it carries.
- [E.10.MOVE - Move and Readiness Wording Precision Restoration (E.10.MOVE)](23-e10move-e10move-move-and-readiness-wording-precision-restoration.md) — Restores the precise meaning hidden by vague words like "move", "step", or "ready" before they silently create a false category in the framework.
- [E.10.ARCH - Wording-Use Ontological Precision Restoration Architecture (E.10.ARCH)](24-e10arch-e10arch-wording-use-ontological-precision-restoration-archit.md) — Distributes wording-repair work across the right patterns so individual patterns stay focused instead of accumulating local synonym catalogues.
- [E.10.P - Conceptual Prefixes policy & registry (E.10.P)](25-e10p-e10p-conceptual-prefixes-policy-registry.md) — Lists all approved short prefixes used as cognitive namespaces in the core and forbids adding new ones without a formal decision record.
- [E.10.D1 - Lexical Discipline for “Context” (D.CTX) (E.10.D)](26-e10d-e10d1-lexical-discipline-for-context-dctx.md) — Locks "Context" to one formal meaning and removes the word "anchor" so teams stop using several different senses interchangeably.
- [E.10.D2 - EntityOfConcern, Description Episteme, and Specification-Use Discipline (E.10.D)](27-e10d-e10d2-entityofconcern-description-episteme-and-specification.md) — Keeps the thing being studied separate from descriptions of it, and descriptions separate from checkable specifications, so these three are never conflated.
- [E.11 - Practical-Use Guidance and Pattern Discovery (E.11)](28-e11-e11-practical-use-guidance-and-pattern-discovery.md) — Governs how the framework helps a practitioner find the right pattern family starting from a real project question rather than from internal topology.
- [E.11.PUA - Pattern Use in a Working Situation and First Useful Result (E.11.PUA)](29-e11pua-e11pua-pattern-use-in-a-working-situation-and-first-useful-r.md) — Turn a promising approach into the smallest useful result right now — knowing what to expect and when to stop.
- [E.11.PUR - Pattern-Use Applicability, Recommendation, and Coordination (E.11.PUR)](30-e11pur-e11pur-pattern-use-applicability-recommendation-and-coordina.md) — Defines the relation for recommending which pattern to apply next for a given concern, without confusing the recommendation with the work itself.
- [E.12 - Didactic Primacy & Cognitive Ergonomics (E.12)](31-e12-e12-didactic-primacy-cognitive-ergonomics.md) — Establishes that human comprehension always outranks theoretical purity so the framework never becomes too dense to use in practice.
- [E.13 - Pragmatic Utility and Value Alignment (E.13)](32-e13-e13-pragmatic-utility-and-value-alignment.md) — Addresses the risk that a visible score or metric becomes the real goal, displacing the practical value the measurement was meant to serve.
- [E.14 - Human‑Centric Working‑Model (E.14)](33-e14-e14-humancentric-workingmodel.md) — Keeps one plain, practitioner-readable working model visible while allowing deeper assurance evidence to sit beneath it without cluttering the text.
- [E.15 - Lexical Authoring & Evolution Protocol  (LEX‑AUTH) (E.15)](34-e15-e15-lexical-authoring-evolution-protocol-lexauth.md) — Defines a repeatable method for proposing, varying, selecting, validating, and publishing pattern changes with a traceable audit trail.
- [E.16 - RoC‑Autonomy Budget & Enforcement (E.16)](35-e16-e16-rocautonomy-budget-enforcement.md) — Requires any claim of autonomous behaviour to declare explicit limits, override procedures, and a ledger so autonomy can be tested and revoked.
- [E.17.0 - U.MultiViewDescribing - Viewpoints, Views & Correspondences (E.17.0)](36-e170-e170-umultiviewdescribing-viewpoints-views-correspondences.md) — Governs how multiple perspectives on the same entity are kept comparable without confusing a diagram or document with the entity itself.
- [E.17.1 - U.ViewpointBundleLibrary - Reusable Viewpoint Bundles (E.17.1)](37-e171-e171-uviewpointbundlelibrary-reusable-viewpoint-bundles.md) — Maintains a stable catalogue of named viewpoint families so teams can import and reuse them without reinventing the same groupings locally.
- [E.17.2 - TEVB - Typical Engineering Viewpoints Bundle (E.17.2)](38-e172-e172-tevb-typical-engineering-viewpoints-bundle.md) — Provides a compact reusable set of four engineering viewpoints (functional, procedural, allocation, interface) for comparing descriptions of the same system.
- [E.17 - Multi‑View Publication Kit (E.17)](39-e17-e17-multiview-publication-kit.md) — Defines how to publish the same source-backed claim in multiple readable forms for different audiences without letting any face become authoritative by itself.
- [E.17.EFP - ExplanationFaithfulnessProfile — explanation-use discipline over existing MVPK faces (E.17.EFP)](40-e17efp-e17efp-explanationfaithfulnessprofile-explanation-use-discip.md) — Classifies explanatory notes as source-pinned, reconstructed, didactic, or speculative so helpful commentary cannot quietly become a second source of truth.
- [E.17.ID.CR - ComparativeReviewUnit - bounded comparison over comparative review units (E.17.ID)](41-e17id-e17idcr-comparativereviewunit-bounded-comparison-over-compar.md) — Defines a small comparison note format that makes one bounded contrast inspectable without the note being mistaken for a decision or approval.
- [E.17.AUD - PublicationUnit Stability Discipline - keep one publication unit stable enough to read honestly (E.17.AUD)](42-e17aud-e17aud-publicationunit-stability-discipline-keep-one-publica.md) — Detects when a memo, note, or table has quietly shifted topic or gained unintended authority, and routes the repair to the right corrective pattern.
- [E.17.AUD.LHR - PublicationUnit Stability Discipline and Local Head Restoration - repair the overloaded local lexical head before the publication unit inherits it (E.17.AUD)](43-e17aud-e17audlhr-publicationunit-stability-discipline-and-local-hea.md) — Repairs a single overloaded word in one sentence before its ambiguity spreads to the rest of the publication unit.
- [E.17.AUD.OOTD - PublicationUnit Stability Discipline and PublicationUnit Primary EntityOfConcern Discipline - publication-unit stability over one primary EntityOfConcern (E.17.AUD)](44-e17aud-e17audootd-publicationunit-stability-discipline-and-publicat.md) — Stops a note or review aid from drifting into a different topic or silently authorising wider work than it was written to cover.
- [E.18 - Transformation Flow Structure (E.18)](45-e18-e18-transformation-flow-structure.md) — Provides a notation-independent structure for mapping how transformations, mechanisms, plans, and results connect in a flow without conflating them.
- [E.18.1 - P2W Problem-to-Work Carry-Through (E.18.1)](46-e181-e181-p2w-problem-to-work-carry-through.md) — Defines the relation that translates an accepted problem analysis into a specific named next step, preventing vague inspiration from substituting for concrete work.
- [E.18.2 - Transformation Flow Mathematical Description (E.18.2)](47-e182-e182-transformation-flow-mathematical-description.md) — Governs how a graph, algebra, or other formal expression describes a selected flow structure without letting the expression authorise work on its own.
- [E.18.3 - Constraint-Governed Transformation-Flow Unfolding Structure (E.18.3)](48-e183-e183-constraint-governed-transformation-flow-unfolding-struc.md) — Capture what really decides the next step in a process flow, without mistaking the drawing for work already done.
- [E.19 - Pattern Quality Gates: Review and Refresh Profiles (E.19)](49-e19-e19-pattern-quality-gates-review-and-refresh-profiles.md) — Turns pattern admission and refresh into a repeatable review profile instead of a matter of reviewer taste or heading compliance.
- [E.20 - Mechanism Introduction Protocol (E.20)](50-e20-e20-mechanism-introduction-protocol.md) — Provides a required protocol for adding or revising a mechanism definition so meaning stays in the right governing location and citeable tokens stay stable.
- [E.21 - FPF Pattern-Quality Evaluation CharacteristicSpace (E.21)](51-e21-e21-fpf-pattern-quality-evaluation-characteristicspace.md) — Scores one pattern against a complete set of quality coordinates for a declared use, producing a clear pass, repair, hold, or refresh result.
- [E.22 - Improvement-Oriented Quality Evaluation Question Framing (E.22)](52-e22-e22-improvement-oriented-quality-evaluation-question-framing.md) — Requires a quality request to specify its purpose, floor, and expected result shape before the evaluator starts so the right evaluation is run.
- [E.23 - Quality Improvement Loop Method (E.23)](53-e23-e23-quality-improvement-loop-method.md) — Defines how to improve an artifact through repeated evaluation passes without drifting into checklist closure or optimising scores instead of content.
- [E.24 - U.Ontic and Ontic Introduction Discipline (E.24)](54-e24-e24-uontic-and-ontic-introduction-discipline.md) — Decides whether a recurring construct deserves a durable governed concept or should stay a local label, preventing shadow ontology from accumulating.
- [E.24.CD - Ontic Candidate Detection (E.24.CD)](55-e24cd-e24cd-ontic-candidate-detection.md) — Identifies which recurring constructs are genuine concept candidates before committing to a full governance decision for any of them.
- [E.24.PUB - Ontic Description and Publication Discipline (E.24.PUB)](56-e24pub-e24pub-ontic-description-and-publication-discipline.md) — Keeps the thing being governed distinct from the pattern that describes it so files and cards are not mistaken for the concepts they publish.
- [E.24.UK - U-kind Governance and Ontic Settlement Coupling (E.24.UK)](57-e24uk-e24uk-u-kind-governance-and-ontic-settlement-coupling.md) — Decides whether a public technical name should be a root concept, a dependent value, or plain wording so names remain trustworthy orientation cues.
