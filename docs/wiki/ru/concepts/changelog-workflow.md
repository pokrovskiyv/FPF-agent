# Рабочий процесс changelog

## Определение

**Рабочий процесс changelog** — это автоматическая плюс ручная пара шагов, которая держит `CHANGELOG.md` и поле `version` в `plugin.json` в синхронизации с каждым коммитом. Сообщения коммитов разбираются по схеме Conventional Commits: `feat:` → minor-бамп, `fix:` → patch-бамп, `feat!:` (или любой тип с `!`) → major-бамп, остальные типы (`docs`, `test`, `chore`, `perf`, `ci`, `style`, `refactor`) → запись в changelog без бампа версии.

Процесс состоит из двух половин: автоматической (PreToolUse-хук, срабатывающий на каждом коммите) и ручной (раздел «Что нового», который пишет человек). Текущая опубликованная версия — **0.6.0**.

## Как это работает в системе

### Автоматическая половина — хук на коммит

Описана в `.claude/settings.json` как PreToolUse-хук на `Bash` с условием `if: Bash(git commit*)`. Перед каждым коммитом он запускает `scripts/update_changelog.py` (см. [update_changelog](../modules/update_changelog.md)), который:

1. Читает JSON хука из stdin.
2. Извлекает первую строку сообщения коммита — поддерживает и форму `-m "..."`, и heredoc-форму Claude Code (`-m "$(cat <<'EOF' ... EOF)"`).
3. Парсит её как Conventional Commit через `CC_PATTERN` — тихо выходит, если не совпало.
4. Определяет бамп (`determine_bump` / `bump_version`) и, если тип `feat` / `fix` / breaking, обновляет поле `version` **только в `.claude-plugin/plugin.json`** (константа `PLUGIN_JSON` указывает именно туда).
5. Добавляет bullet в `CHANGELOG.md` под заголовок с сегодняшней датой, внутри подраздела `### All Changes`.
6. Делает `git add` изменённых файлов (`CHANGELOG.md`, плюс `.claude-plugin/plugin.json`, если был бамп), чтобы они попали в тот же коммит.

Вставка в changelog идемпотентна: повторный коммит с той же темой не дублирует запись (`update_changelog` сверяет строку целиком перед вставкой).

### Ручная половина — раздел «Что нового»

Для изменений, видимых пользователю (`feat:` или значимый `fix:`), Claude или разработчик также пишут строку в подраздел `### What's New` файла `CHANGELOG.md` под сегодняшней датой. CLAUDE.md уточняет: «Пишите на обычном языке с позиции пользователя, не копируйте commit-сообщения. Группируйте связанные изменения в один пункт». Это та часть, которую пользователь действительно читает — примеры в продуктовом тоне (RU и EN) видны прямо в `CHANGELOG.md`.

### Два манифеста плагина, синхронные между собой

Проект поставляется как плагин **для двух** систем: Claude Code (`.claude-plugin/plugin.json`) и Codex CLI (`.codex-plugin/plugin.json`, ставится скриптом `scripts/install_codex_plugin.py` в локальный home-marketplace). Оба манифеста несут одинаковую `version`.

Хук всегда трогает только `.claude-plugin/plugin.json`. Второй манифест приводится в синхрон плановой рутиной [fpf-sync](../agents/fpf-sync.md): её Шаг 7 бампит версию **в обоих** файлах — `.claude-plugin/plugin.json` и `.codex-plugin/plugin.json`, а Шаг 8 добавляет оба в коммит. Поэтому синхронизации, запущенные рутиной, держат манифесты в лок-степе, тогда как разовые коммиты двигают только Claude-Code-версию — Codex-манифест догоняет её на следующей синхронизации.

### Откуда берётся «Что нового» раз в две недели

Регулярные коммиты синхронизации с upstream, наполняющие раздел `### What's New`, производит процесс [sync-and-rebuild](../architecture/sync-and-rebuild.md) — Claude Code Remote Routine, единственный механизм синхронизации (GitHub Action больше нет). Её Шаг 7 пишет видимую пользователю запись «Что нового» и бампит оба манифеста; сообщение коммита — `chore: sync upstream + rebuild + AI-enhanced indexes + wiki refresh`, которое хук затем записывает в `### All Changes`.

## Почему автомат и ручка разделены

- Автоматическая половина фиксирует, **что** изменилось (историю коммитов) — детерминированно и полно.
- Ручная половина фиксирует, **зачем**, на уровне продукта (язык, который читает пользователь) — курируемая история.

Смешение дало бы либо пункты `### What's New — chore(agents): bump description` (бессмысленные для пользователя), либо потребовало бы вызывать LLM в хуке на каждом коммите (медленно и нестабильно). Разделение оставляет детерминированному хуку (меньше секунды) ведение журнала, а человеку — или рутине синхронизации — нарратив.
