# Маршрут 1: Зоны ответственности (Project Alignment)

> Источник: `sections/routes/route-1-project-alignment.md`

## Краткое описание

Срабатывает на формулировки вроде: "команды не понимают друг друга", "зоны ответственности размыты", "кто за что отвечает?", "передаём работу, но граница нечёткая". На выходе — карта "кто за что", потоки передачи работы между командами и перечень пробелов. Сам файл маршрута генерируется скриптом `scripts/build_routes.py` (route id `1`, slug `project-alignment`): для каждого pattern ID цепочки скрипт подставляет заголовок и путь к файлу из `sections/metadata.json`.

## Ключевые решения

- **Длина цепочки:** 8 секций при полной загрузке, 3 отмечены core для минимальной.
- **Core-секции:** `A.1.1` (семантическая рамка U.BoundedContext), `A.15` (согласование роль-метод-работа / контекстное исполнение), `B.5.1` (explore → shape → evidence → operate).
- **Полная цепочка:** добавляет детали плана работ и слотового заполнения (`A.15.2` U.WorkPlan, `A.15.3` SlotFillingsPlanItem), гармонизацию квартета методов (`F.11`), выравнивание и мост между контекстами (`F.9`) и единый термин-лист — Unified Term Sheet (`F.17`).
- **Стратегия загрузки:** минимальная загрузка — первые 3 core-секции для простых запросов; полная — все 8 секций для сложных. При обнаружении застоя ретривер сверяется с `_xref.md` секции для поиска перекрёстных ссылок.

## Статус

Активен. Используется для задачи `project_alignment`, детектируемой классификатором. Шаблон ответа (у резонера): "Зоны ответственности → Потоки работы между командами → Пробелы с ответственными". Цепочка в исходном файле держится в синхронизации с таблицей `ROUTES` в `scripts/build_routes.py`; повторная генерация маршрутов (`python3 scripts/build_routes.py`) перезаписывает этот файл из той таблицы и актуальных метаданных.
