# Route 8: Trust Assurance

> Source: `sections/routes/route-8-trust-assurance.md`

## Summary

Route 8 fires when a user questions whether a number, score, or system can be trusted: "can we trust this metric?", "how do I aggregate confidence without overclaiming?", or "what's the evidence grounding behind this?" It loads the trust-and-assurance calculus so the Reasoner can build an assurance profile — formality, scope, and reliability rated per component — together with a dependency map and an explicit list of evidence gaps. The point is to make the weakest links visible rather than letting a single confident-looking aggregate mask them.

The route is one of the ten practical entry routes. Its section chain is declared as a data record in `scripts/build_routes.py` (`ROUTES[7]`, `id: 8`, `slug: "trust-assurance"`) and rendered to `sections/routes/route-8-trust-assurance.md` by `build_route_file`, which resolves each pattern ID against `sections/metadata.json` to fill in titles and file paths.

## Key Decisions

- **Chain length:** 5 sections total in full load; 3 marked core.
- **Core sections (minimum load):** `B.3` (Trust & Assurance Calculus — F–G–R with congruence), `B.3.5` (Working-Model Relations & Grounding, CT2R-LOG), `B.1` (Holon Aggregation and Part-Whole Construction). These three answer the simple form of the question.
- **Full chain adds:** `B.1.1` (Dependency Structure and Relation Grounding) and `A.6.B` (boundary norm square — laws / admissibility / deontics / work), pulled in for complex queries where aggregation dependencies and boundary obligations matter.
- **Loading strategy:** minimum load = first 3 core sections for a simple query; full load = all 5 for a complex one; on stagnation, consult the section's `_xref.md` for cross-references rather than widening the chain blindly.
- **Generated, not hand-edited:** the route file is regenerated by `build_routes.py` from the `ROUTES` table, so the chain stays in lockstep with the canonical pattern IDs and any title/path changes in `metadata.json`.
