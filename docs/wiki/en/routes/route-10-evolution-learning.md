# Route 10: Evolution Learning

> Source: `sections/routes/route-10-evolution-learning.md`

## Summary

Triggered when the design is outdated and nobody noticed, the feedback loop between operations and design is broken, or lessons learned keep recurring. The user gets a current cycle map showing where the loop is broken, a loop-closure plan, and cycle-health indicators. The route is one of the ten Tier-1 entry routes generated by `scripts/build_routes.py` (route `id: 10`, slug `evolution-learning`), which resolves each pattern ID to its title and file path from `sections/metadata.json`.

## Key Decisions

- **Chain length:** 5 sections in full load, 3 core (defined as `chain` and `core` in the route's entry inside `build_routes.py`).
- **Core sections:** `B.4` (Canonical Evolution Loop), `B.4.1` (Observe → Notice → Stabilize → Route), `B.5.1` (Explore → Shape → Evidence → Operate).
- **Full chain:** adds `A.4` (Temporal Duality & Open-Ended Evolution Principle) and `G.11` (Telemetry-Driven Refresh & Decay Orchestrator).
- **Loading strategy:** minimum load pulls the first 3 core sections for simple queries; full load pulls all 5 for complex ones; if stagnation is detected, the retriever checks `_xref.md` for cross-references.

## Status

Active. Used for the `evolution_learning` burden. Reasoner output shape: "Current cycle map → Break point → Loop closure plan → Cycle health indicators". The file is regenerated whenever `scripts/build_routes.py` runs (part of the rebuild pipeline), so edits go to the generator and metadata, not the route file directly.
