# Route 3: Boundary Unpacking

> Source: `sections/routes/route-3-boundary-unpacking.md`

## Summary

Route 3 is triggered when the user brings a contract, API spec, SLA, or technical specification that mixes rules, conditions, obligations, and evidence requirements into one undifferentiated soup. The output is a structured breakdown that separates the four kinds of statements: what is a rule, what is an access condition, what is an obligation, and what needs to be proven. The route is one of the ten practical entry points; its section chain is generated by `scripts/build_routes.py` from the `chain`/`core` lists keyed by pattern ID against `sections/metadata.json`.

## Key Decisions

- **Chain length:** 6 sections in full load, 3 core. Defined in `build_routes.py` as `chain: ["A.6", "A.6.B", "A.6.C", "A.6.P", "A.6.Q", "A.6.A"]` with `core: ["A.6", "A.6.B", "A.6.C"]`.
- **Core sections:** `A.6` (Signature Stack & Boundary Discipline), `A.6.B` (Boundary Norm Square — Laws / Admissibility / Deontics / Work), `A.6.C` (Contract Unpacking for Boundaries). These three carry the four-quadrant separation the route promises.
- **Full chain:** adds relational precision restoration (`A.6.P`), quality-term precision (`A.6.Q`), and action-invitation precision (`A.6.A`). All chain entries live in the same cluster directory, `sections/06-cluster-aiva-signature-stack-boundary-discipline-a6/`.
- **Resolution note:** the generator looks each pattern ID up in `sections/metadata.json`. `A.6.Q` currently resolves to `(not found)` with no file path, and `A.6.A` maps back to the `A.6` source file — both are reflected verbatim in the generated route file and will self-correct on the next rebuild if metadata changes.
- **Loading strategy:** minimum load is the first 3 core sections for a simple query; full load is all 6 for a complex one. On stagnation, the retriever falls back to `_xref.md` cross-references for the cluster.

## Status

Active. Used for the `boundary_unpacking` burden. The route file is regenerated by `scripts/build_routes.py` as part of `scripts/rebuild_all.sh`, so its section chain and pattern references stay in sync with `FPF-Spec.md`. The Reasoner applies a fixed four-quadrant template — "Rules / Access conditions / Obligations / Evidence required" — without exposing any framework terminology to the user.
