# Route 9: Composition Aggregation

> Source: `sections/routes/route-9-composition-aggregation.md`

## Summary

Triggered when KPIs lie, the sum of parts does not equal the whole, or Tool A aggregates differently from Tool B. The route loads a chain of Part B sections covering the algebra of aggregation and its system-, knowledge-, contextual/temporal-, and method-specific variants. Output is a diagnosis of which composition rules were violated, an aggregation dependency map, and concrete fix recommendations.

The route file itself is generated by `scripts/build_routes.py` from the `ROUTES` table (entry `id: 9`, slug `composition-aggregation`); section titles and file paths are resolved against `sections/metadata.json`, so the chain stays in sync with the spec on every rebuild.

## Key Decisions

- **Chain length:** 6 sections in full load, 3 marked core.
- **Core sections** (minimum load for simple queries): `B.1` (Holon Aggregation and Part-Whole Construction), `B.1.1` (Dependency Structure and Relation Grounding), `B.1.4` (Contextual and Temporal Aggregation).
- **Full chain** (complex queries) adds: `B.1.2` (System Aggregation and Holon Delimitation), `B.1.3` (Γ_epist — Knowledge-Specific Aggregation), `B.1.5` (Γ_method — Order-Sensitive Method Composition & Work Enactment).
- **Stagnation fallback:** if loading the chain stalls, check the relevant `_xref.md` for cross-references.

## Status

Active. Used for the `composition_aggregation` coordination burden. Reasoner output pattern: "Diagnosis (violated invariants) → Dependency map → Fix recommendations". Generated and kept current by `scripts/build_routes.py` as part of `scripts/rebuild_all.sh`.
